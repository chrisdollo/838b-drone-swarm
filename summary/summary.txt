PROJECT SUMMARY (technical)
Decentralized Swarm Shape Formation via Differentiable Simulation
State as of Nov 20, 2026 (v3). Details: docs/phases_explained.txt and the walkthroughs in docs/walkthrough/.

Idea: every drone runs the same small neural network on what it sees. The network
is trained by backpropagating a formation loss through a differentiable physics
simulator (PyTorch), not by reinforcement learning or hand-written rules.


==============================================================================
PHASE 1. DIFFERENTIABLE SIMULATOR + TOY OPTIMIZATION
==============================================================================

Goal
  Prove that a loss on the drones' FINAL positions can be backpropagated through
  100 physics steps to the accelerations that produced them, before any network.

Simulator (swarm/sim.py)
  Point-mass drones, state [B, N, 2] (batch, drones, xy), semi-implicit Euler:
    v_{t+1} = (1 - c*dt) v_t + dt * a_t        p_{t+1} = p_t + dt * v_{t+1}
  dt = 0.05 s, T = 100 steps (5 s), damping c = 0.5 (lambda = 1 - c*dt = 0.975),
  a_max = 2. PyTorch ops only, no in-place ops, so autograd sees every step.
  Unrolled: p_T = p_0 + sum_s w_s a_s with w_s = (dt/c)(1 - lambda^(T-s)), so the
  gradient w.r.t. an early action is ~37x that of the last one; damping caps it.

What is optimized: r, not a
  The parameters are raw numbers r [1, T, N, 2] (6,400 for 32 drones) and
      a = a_max * tanh(r)
  - Every r maps to exactly one a in (-2, 2): optimizing r IS optimizing a,
    but no value of r can break the motor limit.
  - Clipping a instead would give zero gradient past the limit (stuck actions);
    tanh always has a nonzero slope.
  - Phase 2 puts the same a_max * tanh(.) on the network's output, so Phase 1
    already tests that exact path.

Loss: Chamfer distance (swarm/losses.py)
  L = mean_i min_j |p_i - q_j|^2  +  mean_j min_i |p_i - q_j|^2
      (every drone near some goal)  (every goal near some drone)
  No drone is assigned a goal. Both terms are needed: the first alone lets all
  drones pile on one point. Squared distances are computed directly (not cdist,
  whose sqrt has an infinite slope at 0).

Toy optimization (swarm/plan.py: optimize_plan)
  32 drones, random starts, 64 goal points, Adam lr 0.05, 300 iterations,
  cosine learning-rate decay.
    circle: loss 0.0327 -> 0.00065 (best possible ~0.00058 = 3/8 s^2)
    square: 0.0312 -> 0.00109 (earlier script run; the notebook now runs the circle)
  Lessons:
  - A constant lr diverges near the optimum (0.00062 -> 0.027): Adam moves every
    parameter by ~lr however small its gradient. Cosine decay fixes it.
  - The best loss is not 0: with 2 goals per drone, each drone's best spot is a
    quarter of the way between two goals.
  - A fixed plan only works for its own scene: replayed from 15 new starts it
    scores 0.162 (worse than not moving, 0.033). Hence Phase 2.

GIFs and figures (Phase 1)
  results/gifs/phase1_circle.gif    the optimized plan replayed: 32 drones from
                                    random starts onto the circle, 100 steps
  results/figures/phase1_loss.png   loss per iteration vs the best possible
  results/figures/phase1_lr.png     constant lr 0.05 / 0.01 vs cosine decay

Notebook: notebooks/phase1.ipynb (~1 min)
  1 setup and config
  2 gradient check: measured |grad| per step matches w_s (ratio 36.8)
  3 target shapes (circle, square, line, star)
  4 Chamfer worked example (2 drones, 4 goals: L = 0.01 + 0.25)
  5 toy optimization -> GIF + loss curve
  6 learning-rate comparison
  7 fixed plan on new starts / another shape / missing drones


==============================================================================
PHASE 2. SHARED DECENTRALIZED POLICY
==============================================================================

Goal
  One network, copied onto every drone, maps what that drone sees to an
  acceleration. Centralized training (whole swarm, one loss, offline),
  decentralized execution (each drone uses only its own observation).

Network (swarm/observations.py, swarm/policy.py)
  Input, 39 numbers per drone, all relative to the drone:
    6 nearest drones          p_j - p_i                 12
    8 nearest goals           q_l - p_i                 16
    "is each goal taken?"     distance from that goal to the nearest OTHER drone   8
    collision distance d_min  (mission parameter)        1
    own velocity              v_i                        2
  Same size for any N; unchanged if the scene shifts; no drone identities.
  Which neighbors/goals are nearest is chosen without gradient; the offsets
  and distances themselves are differentiable.
  MLP 39 -> 64 -> 64 -> 2, SiLU (smooth), a = a_max * tanh(output);
  6,850 weights shared by every drone. Distances x10 before the first layer;
  output layer initialized tiny (untrained swarm barely moves).

Training data (swarm/dataset.py), generated on the fly, no dataset on disk
  - Grid of (drones N, goals M): 8:{8,16,32,64}, 16:{16,32,64}, 32:{32,64},
    64:{64,128}. Each iteration picks one cell at random.
  - Shapes = lists of strokes, randomly rotated, stretched, sized, shifted.
      training families: circle, square, line, triangle, pentagon, random
                         polygon, random polyline, 1-2 letters
      held out (never trained on): star, heart, spiral, words
                         (HI, UMD, LOVE, FIRE, MARRY ME)
  - Feature-size rule: parts far apart along the shape must be at least one
    drone spacing s = outline length / N apart in space, else the shape is
    redrawn (the swarm could not draw it). The trained models used a 3s
    along-the-shape threshold; it is now 6s, for the new text layout.
  - Collision distance per scene: d_min = 0.4 s.
  - Start positions uniform in the box [-0.5, 0.5]^2, at rest.
  - Fixed benchmark (data/benchmark/, 468 scenes): per cell 32 scenes of
    training families + up to 16 of held-out families, each with its PER-SCENE
    OPTIMUM (Phase 1 method on that scene, same collision penalty).

How training works (swarm/train.py)
  each iteration:
    1. pick a grid cell, draw 32 scenes (batch)
    2. closed loop for T steps: observe -> policy -> sim.step
       (curriculum: T = 40 from it 0, 70 from it 500, 100 from it 1000)
    3. loss (below), averaged over the 32 scenes
    4. loss.backward() through every step and every policy call (BPTT)
    5. clip gradient norm to 1, Adam step, cosine lr step
  every 250 iterations: score the benchmark (training families), keep the best

Loss (swarm/losses.py: total_loss), per scene, s = drone spacing:
  L = [ shape + 10 * collision (+ 1.0 * spacing) ] / s^2  +  0.01 * effort
  - shape: Chamfer averaged over the last 20% of steps (arrive AND stay)
  - collision: sum over pairs closer than d_min of (d_min - distance)^2, all steps
  - spacing (optional, the "spacing" experiment): same form with radius 0.8 s,
    last 20% of steps (PU-Net-style repulsion: pushes toward even spacing)
  - effort: mean |a|^2
  - divided by s^2 because those terms scale with s^2: otherwise sparse
    8-drone scenes would weigh ~30x more than dense 64-drone ones

Optimizer and settings (configs/default.yaml)
  Adam, lr 0.003 -> 0.0003 cosine over 3,000 iterations (Phase 1 lesson),
  batch 32, gradient-norm clip 1.0, truncated BPTT off.
  Note: with the s^2 normalization, gradient norms are 1-1000, so clipping is
  active almost every step (normalized gradient descent in practice).

Early stopping
  Yes: stop when the benchmark score has not improved by >= 1% for 4 checks
  (1,000 iterations). It did not trigger in either run (both still improving
  after iteration 2,250). The best checkpoint is always kept.

Score
  ratio = (Chamfer + eps) / (per-scene optimum + eps), eps = 0.01 s^2,
  geometric mean over scenes. 1x = as good as optimizing that scene directly.
  Also: close pairs (< d_min) and unevenness (std/mean of nearest-neighbor
  distance, 0 = perfectly even).

Results (3,000 iterations, 16 min each on a laptop CPU)
                              baseline     spacing     per-scene optimum
  ratio, training families    2.23x        2.19x       1x
  ratio, held-out families    2.25x        2.34x       1x
  close pairs per scene       6.1          3.2         2.2
  unevenness                  0.433        0.307       0.340
  drones crowding (<0.4 s)    20.6%        9.9%        13.9%
  - Strong with >= 2 goals per drone (1.3-2.4x); weak with 1 goal per drone
    (3-6.5x, even the optimum ends with two drones sharing a goal).
  - Held-out shapes cost (almost) nothing: generalization works.
  - New starts on a circle: Phase 1 fixed plan 0.167 vs policy 0.00049.
  - Spacing term: half the crowding, more even than the optimum, same training
    error; slightly worse on held-out shapes and on MARRY ME (64 drones).
  - Score plateaus after ~1,250 iterations: more training won't help.
  Models: results/models/phase2_baseline.pt, phase2_spacing.pt

==============================================================================
PHASE 2, VERSION 3: ONE GOAL SLOT PER DRONE (current)
==============================================================================

Direction: slot-based formation, drones = goals (M = N); decentralized,
communication-free, learned via differentiable physics, to be compared with a
centralized Hungarian-assignment baseline in Phase 3.

Goal layout (swarm/layout.py), now used for EVERY shape family
  - A slot at every stroke end, corner (turn > 35 deg) and junction
    ("anchors"; close anchors merged), the rest filled into the widest gaps,
    no two slots closer than 0.6 spacings. Exactly N slots for N drones.
  - Text: Hershey Simplex single-stroke font, A-Z and 0-9 (digits checked).
    fewest_readable(text) = fewest drones that keep it readable.

What changed from v2 (details: docs/phases_explained.txt, "VERSION 3")
  - N drawn uniformly from 8-96 for every batch; M = N.
  - Training families add random strings (1-4 letters/digits); "letters" is
    1-2 letters. A string is used only if readable for the batch's N.
  - Held out: star, heart, spiral, words HI UMD LOVE FIRE MARRY ME, and 12
    fixed strings (seed 838: 8 A 63 22 NY4 ODP PH0 0TO 6F2L G CS W), all
    excluded from the training sampler.
  - Benchmark data/benchmark_v3 (seed 2026 + 100 i + split): N = 8, 16, 24,
    32, 48, 64, 96; 4 scenes per family; per-scene optimum stored.
  - Scores (swarm/metrics.py), drones matched one-to-one to slots (Hungarian):
      slots filled  share of slots with their drone within d_min
      slot error    mean matched distance in drone spacings
      steps to form first step after which slot error stays < 0.5 spacings
      shared goals  share of slots that are the nearest slot of 2+ drones
  - Model selection / early stopping on mean slot error.
  - Phase 1 text plans score the shape at every step (hold_frac=1.0) so the
    drones move fast and hold, instead of arriving just as the run ends.
  - Outputs tagged phase2_v3_*; v2 models/results kept, v2 notebooks in
    notebooks/v2/.

Results (same v3 benchmark, mean over N; training / held-out shapes)
                 slots filled   slot error    shared goals  close pairs
  v2 spacing       40% / 46%    2.54 / 1.39      18%          11.8
  v3 baseline      29% / 37%    1.84 / 1.30      25%          15.1
  v3 spacing       42% / 50%    1.60 / 1.18      19%           6.8
  optimum          72% / 76%    1.20 / 0.98      12%           8.4
  Words (v3 spacing): UMD 72%, LOVE 65%, FIRE 52%, HI 50%, MARRY ME 33%.

Problems
  1. Chamfer has no one-to-one constraint: training loss falls while slot
     error rises; ~19% of slots doubled up; even the optimum fills only 72%.
     Proposed (not added): a Sinkhorn / soft-matching loss term.
  2. Corners and stroke ends are the empty slots (41% vs 49% for fill slots).
  3. Slot error and slots filled disagree late in training, so early
     stopping on slot error kept an early v3 baseline checkpoint (29% filled
     vs 37% at the end). Select on slots filled next time.
  4. Filling drops with swarm size (55% at 8 drones -> 33% at 96).


Next phases after that

Phase 3, baseline comparison (the main result). Hungarian assignment plus straight or smooth paths, run through the same simulator with the same acceleration limit. Compare on shape error, slots filled, steps to form (first step where error drops below a threshold), collisions, and effort.
Phase 4, failure recovery (evaluation only). Remove k drones mid-flight and regenerate goals for N−k drones with text_goals. Your policy just keeps running, while the baseline has to re-run Hungarian and replan. Measure the time to re-form.
Phase 5, 3D. This was planned for the Nov 17 midpoint, so you’re behind on it. It’s a small code change ([B, N, 3]), but the text layout needs a plane or a projection. Do it only if Phases 3 and 4 are done.
Phase 6, demo and report (Dec 17). A browser demo where you type text and watch the swarm form it and recover from a failure, plus the final report.
