==============================================================================
PHASE 1. SETUP AND FOUNDATIONS
==============================================================================

------------------------------------------------------------------------------
1. BIG PICTURE
------------------------------------------------------------------------------

Goal: prove that gradients flow through our own simulator before any neural
network is involved.

The test: 32 agents start at random positions. We do not use a policy.
Instead, we directly optimize the full list of accelerations (every agent,
every time step). We run the simulation, measure how far the final positions
are from a circle, backpropagate that error through all 100 steps, and update
the accelerations. Repeat 300 times.

If the agents end up forming a circle, then three things are correct:
  - the simulator is differentiable
  - the shape loss is correct
  - autograd connects the loss to the actions through every step

Why do this first: in Phase 2 the accelerations come from a neural network.
If training fails there, we will know the bug is in the network or the
observations, not in the simulator or the loss.

The pipeline:

  raw params --tanh--> accelerations --sim.rollout--> final positions
                                                           |
  Adam <-- gradient (BPTT) <-- Chamfer loss vs circle <----+

What exactly we optimize:
  The accelerations. 32 drones x 100 steps x 2 directions (x, y) = 6,400
  numbers: what each drone's motors do at each moment.

  We store them as raw numbers r and compute a = a_max * tanh(r).
    - tanh squashes any number into (-1, 1), so a always stays in [-2, 2].
    - Each r gives exactly one a, so choosing r = choosing a.
      r = 0 -> a = 0,  r = 1 -> a = 1.52,  r = 1000 -> a = 2 (never more).

  Why a limit at all: a_max = 2 is the motor limit (max 2 units/s^2 in x
  and in y). Without it the optimizer cheats: huge accelerations, and the
  drones jump onto the circle in one frame. The box is 1 unit wide, so the
  limit still leaves plenty of reach.

  Why not optimize a directly and clip it:
    - clamp(a, -2, 2) inside the sim gives 0 gradient past the limit, so
      that action gets stuck. tanh always has a nonzero slope.
    - Clipping after each Adam step would work for Phase 1.
    - The real reason is Phase 2: the network's output goes through the
      same a = a_max * tanh(output). Phase 1 tests that exact path. Only
      the source of r changes:
        Phase 1: r = 6,400 free numbers     -> tanh -> simulator
        Phase 2: r = MLP(drone observation) -> tanh -> simulator

3. FILE BY FILE
------------------------------------------------------------------------------

--- configs/default.yaml -----------------------------------------------------

  dim: 2         Spatial dimension (2D). Set to 3 later for 3D.
  n_agents: 32   Number of agents N.
  dt: 0.05       Seconds per simulation step.
  steps: 100     Rollout length T. dt * steps = 5 seconds of motion.
  damping: 0.5   Drag coefficient c. Slows agents down each step.
  a_max: 2.0     Maximum acceleration. Actions are a_max * tanh(raw).
  seed: 0        Random seed, so every run is repeatable.

Why define them now:
  - Every later phase uses the same simulator settings. If they lived inside
    the code, the baselines and experiments could silently use different
    values, and the comparisons would be unfair.
  - One file per run means any result can be reproduced from its config.
  - dim is a setting from day one, so switching to 3D is a one-line change.

Why these values:
  - dt * steps = 5 s gives agents enough time to cross the unit box.
  - damping > 0 shrinks velocity a little each step. That keeps agents from
    drifting forever and keeps gradients from exploding over 100 steps.
  - a_max mimics real motor limits.

--- swarm/config.py ----------------------------------------------------------

  load_config(path) reads the YAML and returns an object with attribute
  access (cfg.dt instead of cfg["dt"]). Every script calls it first.

--- swarm/sim.py -------------------------------------------------------------

What it does: moves every agent forward in time. All state tensors have
shape [B, N, dim] (batch, agents, dimension).

  step(pos, vel, acc, dt, damping)
    One time step:
      v_new = (1 - c*dt) * v + a * dt     acceleration changes velocity
      p_new = p + v_new * dt              velocity changes position
    Uses the NEW velocity to update position (semi-implicit Euler), which is
    more stable than using the old one.

  rollout(pos0, vel0, accs, cfg)
    Calls step T times and returns the whole trajectory, shape
    [B, T+1, N, dim]. We keep every frame (not just the last) because the
    GIF needs all of them, and so will the Phase 2 collision penalty.

Rules that keep it differentiable:
  - Only PyTorch operations. No NumPy, no .item(), no .numpy() in the loop:
    each of these cuts the gradient chain.
  - No in-place ops (+=). Autograd needs the old values for the backward
    pass.

Check we ran: gradients reached every time step. Early actions get about
37x larger gradients than the last one because they have more time to move
the agent. Damping is what caps that ratio near 37 instead of 100.

Phase 2 change: accs[:, t] is replaced by the policy's output at step t.

--- swarm/shapes.py ----------------------------------------------------------

What it does: makes the target shape as a set of points Q, shape [M, dim].
A shape is just points, so the loss works the same for any shape.

Conventions:
  - The world is the box [-0.5, 0.5]. Every shape is centered at 0 and
    scaled so its larger side is EXTENT = 0.8, leaving a 0.1 margin.
  - We use M = 2N = 64 points so the shape is densely described.
  - For dim = 3 the shape lies flat at z = 0.

  sample_shape(name, m, dim, vertices=None, closed=False)
    circle    q_j = 0.4 (cos(2 pi j/m), sin(2 pi j/m)), evenly spaced angles
    square    closed polyline through the 4 corners
    line      open polyline, 2 endpoints
    polyline  any vertex list (letters, user drawings); closed=True joins
              the end back to the start

  sample_polyline(vertices, m, closed)
    Places m points evenly by ARC LENGTH along the whole outline, not per
    edge. So a long edge gets more points than a short one and the shape is
    covered uniformly. How: add up segment lengths, pick m evenly spaced
    distances along the total, and interpolate inside the segment each one
    falls in. A closed shape stops one gap short, so the last point does
    not duplicate the first.

  normalize(points)
    Centers the bounding box and scales its larger side to 0.8, so a
    user-drawn shape of any size fits the box.

Check we ran: every shape gives 64 points within [-0.4, 0.4]. Spacing is
even (circle 0.039, square 0.050, line 0.013). For the letter L, points are
evenly spaced along the outline; only the jump across the corner is shorter.

Why this matters later: Phase 2 samples a random shape per batch, and
Phase 4 tests on unseen shapes. Both just call sample_shape.

--- swarm/losses.py ----------------------------------------------------------

What it does: scores how well the agents cover the shape.

  chamfer(P, Q)
    P: agents [B, N, dim]. Q: targets [B, M, dim] or [M, dim].
    D[i, j] = ||p_i - q_j||^2 for every agent/target pair, then
      A = mean over agents of (distance to nearest target)   no stragglers
      B = mean over targets of (distance to nearest agent)   no gaps
      L = A + B, averaged over the batch.
    No agent is assigned a target; each min picks the nearest one right now.
    Both terms are needed: with A alone, all agents can pile onto one point.

  pairwise_sq_dist(P, Q)
    Builds D from coordinate differences instead of torch.cdist(P, Q) ** 2.
    cdist takes a square root and we would square it again; the square root
    has an infinite slope at distance 0 (agent exactly on a target point).
    This form is exact and smooth everywhere.

Phase 2 adds the collision and effort penalties to this file.

--- swarm/viz.py -------------------------------------------------------------

What it does: turns results into pictures. No gradients needed, so tensors
are detached first.

  save_gif(traj, Q, path)    One rollout as a GIF: target points as hollow
                             circles, agents as dots, a step counter. Holds the
                             last frame for 1 s before looping.
  plot_loss(history, path)   Loss per iteration on a log scale, with an
                             optional "best possible" reference line.

--- swarm/plan.py + notebooks/phase1.ipynb -----------------------------------

  optimize_plan(pos0, Q, cfg, iters=300, lr=0.05, cosine=True,
                d_min=None, w_collision=0)
    Optimizes the accelerations of one or more known scenes directly:
  1. raw = zeros [S, T, N, 2], requires_grad. Adam, lr 0.05.
  2. 300 times: a = a_max * tanh(raw) -> rollout -> chamfer(final, Q)
     (+ collision penalty if d_min is given) -> backward -> Adam step
     -> cosine lr step.
  3. Returns the accelerations, the trajectory and the loss history.
  Phase 2 reuses it as the per-scene optimum of the benchmark.

  notebooks/phase1.ipynb runs the whole phase: the gradient check of sim.py,
  the shapes, the Chamfer worked example, the toy optimization (saves
  results/gifs/phase1_circle.gif and results/figures/phase1_loss.png), the
  learning-rate comparison (phase1_lr.png), and the fixed plan replayed from
  new starts (why Phase 2 is needed).

Result: circle loss 0.033 -> 0.00065 in 0.7 s. Best possible is ~0.00058.
Square: 0.031 -> 0.0011.

The learning rate decays to 0 (cosine schedule). Without it the run fails;
see "Surprise" below.

--- tests/ -------------------------------------------------------------------

Run: uv run pytest   (25 tests, about 2 s)

  test_sim.py      rollout output shape; constant velocity when a = c = 0;
                   velocity decays as lambda^t without thrust; final position
                   equals the closed form p_0 + sum w_s a_s; gradcheck on step.
  test_shapes.py   right point count, inside the box; circle radius 0.4;
                   even spacing on closed shapes; polyline normalized to 0.8;
                   3D lies flat; unknown name raises.
  test_losses.py   chamfer(P, P) = 0; symmetric; worked example = 0.26;
                   collapsing onto one point is penalized; gradcheck.

gradcheck compares autograd's gradient to a finite-difference estimate in
float64. If they agree, the backward pass is correct.

pyproject.toml got a [tool.pytest.ini_options] block so tests can import
swarm from the repo root.


------------------------------------------------------------------------------
SURPRISE (for the progress report)
------------------------------------------------------------------------------

1. A constant learning rate breaks the toy optimization.
   With Adam at lr 0.05 the loss reaches 0.00062 by iteration ~185, then
   climbs back to 0.027 by iteration 300. Saturation is not the cause
   (|raw| stays below 0.1). Adam steps every parameter by about lr however
   small its gradient is. One aligned step can move a final position by up
   to a_max * lr * sum(w_s) = 2 * 0.05 * 6.41 = 0.64 units, while the
   target points are 0.04 apart. Near the optimum the agents keep
   overshooting.
     constant lr 0.05:  best 0.00062, final 0.027
     constant lr 0.01:  final 0.00078 (stable, slower)
     cosine from 0.05:  final 0.00065 (stable)  <- used
   The same effect causes the loss spike to ~0.3 in the first iterations.

2. The best loss is not 0, and the best spot is not on a target point.
   With M = 2N, each agent covers two points a spacing s apart. Sitting a
   quarter of the way between them gives A = s^2/16, B = 5 s^2/16, so
   L = 3/8 s^2 = 0.00058. The optimizer reaches 0.00065.

3. Agents arrive only at the end. The loss scores only the final positions,
   so at step 50 the swarm is still scattered. Phase 2 can add a loss on
   intermediate steps if earlier arrival is wanted.

==============================================================================
PHASE 2. POLICY AND TRAINING
==============================================================================

Run: notebooks/phase2.ipynb (~20 min: training 16 min + scoring and GIFs).
Math and figures: docs/walkthrough/phase2.html.

------------------------------------------------------------------------------
1. BIG PICTURE
------------------------------------------------------------------------------

Goal: replace Phase 1's fixed script of accelerations with ONE small neural
network that every drone carries and runs on what it sees.

  Phase 1:  a = a_max * tanh( raw[t] )                         fixed table
  Phase 2:  a = a_max * tanh( MLP_theta( observe(...) ) )       every step

Why: the Phase 1 plan only works for the start it was optimized for (0.167
on new starts, worse than not moving). A policy reacts to the current state,
so it works from any start, for any shape and swarm size, and keeps working
when drones are lost.

Centralized training, decentralized execution: training simulates the whole
swarm with one swarm-wide loss (once, offline); at run time each drone only
uses its own observation and its own copy of the network.

One training iteration:
  1. pick a grid cell (N drones, M goals) at random
  2. make 32 random scenes for it (random start, random training shape,
     collision distance d_min per scene)
  3. closed loop, T times: observe -> policy -> sim.step
  4. loss = shape (last 20% of steps) + collision + effort, per scene / s^2
  5. backward through every step and every policy call, clip, Adam step
  every 250 iterations: score the benchmark against its per-scene optimum

What gets trained: the 6,850 MLP weights, shared by all drones. There is no
dataset to learn from: training scenes are generated on the fly. The fixed
benchmark is only for scoring.

This is version 2. Version 1 (32 drones, 64 goals, fixed d_min = 0.02, no
"is this goal taken" input) worked but clumped, crowded and failed on text;
see section 5.


------------------------------------------------------------------------------
2. THE DATA (swarm/dataset.py)
------------------------------------------------------------------------------

Grid of (drones N, goals M):
  8: 8, 16, 32, 64    16: 16, 32, 64    32: 32, 64    64: 64, 128
M/N matters: M = N means ~one goal per drone (crisp, hard); M = 8N means
each drone covers a stretch of outline.

Shapes are lists of strokes (polylines), randomly rotated, stretched, sized
and placed.
  Training: circle, square, line, triangle, pentagon, random polygon,
            random polyline, 1-2 letters (single-stroke A-Z font)
  Held out: star, heart, spiral, words HI, UMD, LOVE, FIRE, MARRY ME

Feature-size rule (can the swarm draw it?). Drone spacing s = length / N.
Any two points more than 3 s apart ALONG the shape must be at least 1.0 s
apart in SPACE. "Along the shape" = shortest path through a fine sampling
of the strokes, with touching strokes connected (the bar of a T, the bowl
of an R). Rejects double outlines, letters too close, turns of a spiral.
  Minimum drones: HI 10, UMD/LOVE/FIRE 24, MARRY ME 52. A spiral needs 16.

Collision distance per scene: d_min = 0.4 * s. Too loose for 8 drones and
impossible for 64 if fixed; scaled, the task is always feasible.

Benchmark (data/benchmark/, 468 scenes): per cell, 32 scenes of training
families and up to 16 of held-out families. Each scene stores its per-scene
OPTIMUM: the Phase 1 method (swarm/plan.py) optimizing that scene's own
accelerations, with the same collision penalty. Every method is reported as

  ratio = (Chamfer + eps) / (optimum + eps),   eps = 0.01 * s^2

1.0 = as good as optimizing that exact scene. eps keeps the ratio sane when
the optimum is ~0 (8 drones exactly on 8 goals).

  feature_ratio(strokes, N)  the feature-size rule (>= 1.0 to pass)

  build_benchmark / oracle   fixed scenes + per-scene optimum, saved to disk
  load_cell(N, M, split)     read one benchmark cell

--- swarm/observations.py ----------------------------------------------------

Each drone sees 39 numbers:
  [6 nearest drones: p_j - p_i | 8 nearest goals: q_l - p_i |
   for each goal: distance to the nearest OTHER drone | d_min | v_i]
The occupancy ("is this goal taken?": small = taken) is new in v2 and fixes
v1's clumping. It is still local: it only concerns goals near the drone.
Same size for any N, unchanged if the scene shifts, no drone identities.
Which neighbors/goals are nearest is chosen without gradients; the offsets
and occupancy distances stay differentiable.

--- swarm/policy.py ----------------------------------------------------------

  SharedMLP: 39 -> 64 -> 64 -> 2, SiLU, a = a_max * tanh(out), 6,850 weights.
  Distances x10, velocity x1 before the first layer; output layer starts tiny
  (untrained swarm barely moves).
  act(pos, vel, Q, d_min): the controller interface. Phase 3 baselines will
  use the same signature: controller(pos, vel, Q, d_min) -> acc.

--- swarm/sim.py (Phase 2 additions) -----------------------------------------

  rollout_closed_loop(pos0, vel0, Q, d_min, controller, cfg, steps, tbptt)
  rollout_with_removal(...)   self-healing test: delete drones at step t

--- swarm/losses.py (Phase 2 additions) --------------------------------------

  L = [ shape + 10 * collision ] / s^2 + 0.01 * effort, averaged over scenes
  shape_loss      Chamfer averaged over the last 20% of steps (arrive and stay)
  collision_loss  (d_min - distance)^2 for pairs closer than the scene's d_min
  effort_loss     mean ||a||^2
  Dividing by s^2: both terms are squared distances, so an 8-drone scene
  would weigh ~30x a 64-drone scene without it.

--- swarm/plan.py ------------------------------------------------------------

  optimize_plan(...): the Phase 1 optimizer, here used as the benchmark's
  per-scene optimum (with the collision penalty).

--- swarm/train.py -----------------------------------------------------------

  train(cfg, run_dir, callback)   the loop of section 1; saves
                                  runs/phase2/best.pt, last.pt, history.json
  evaluate_cell / evaluate_benchmark / overall_ratio
                                  score any controller against the optimum

--- swarm/viz.py (Phase 2 additions) -----------------------------------------

------------------------------------------------------------------------------
5. SURPRISES AND LESSONS (for the reports)
------------------------------------------------------------------------------

Version 1 -> version 2:
  1. Clumping: drones piled onto goals already taken. Fix: occupancy input.
  2. Fixed d_min = 0.02 was impossible on dense shapes (~11 close pairs per
     scene, 40 on lines). Fix: d_min = 0.4 x spacing, told to every drone.
  3. Text and images failed: their details (double outlines) were finer than
     the drone spacing. Fix: single-stroke font + feature-size rule.
  4. A fixed 32/64 setup hid how the task depends on goals per drone.
     Fix: the drones x goals grid and a benchmark with per-scene optimum.

Version 2:
  5. One goal per drone (M = N) is the hard case: 3-6.5x, and even the
     per-scene optimum ends with two drones sharing a goal.
  6. Dense swarms crowd: ~25 close pairs with 64 drones vs 1-12 for the
     optimum.
  7. Normalizing the loss by s^2 made gradients hundreds of times larger,
     so clipping at 1 is active almost every step (normalized gradient
     descent in practice). The clip threshold is now an important setting.
  8. The score plateaus after ~1,250 iterations: longer training won't help;
     the observation, network size or collision weight would.
  9. The ratio needs a floor: without eps, 8 drones exactly on 8 goals gave
     "1,800x" from a difference nobody could see.

==============================================================================
PHASE 2, VERSION 3: ONE GOAL SLOT PER DRONE
==============================================================================

Direction (decided): slot-based formation, drones = goals (M = N). The pitch
is "decentralized, communication-free, learned formation via differentiable
physics" against a centralized Hungarian-assignment baseline (Phase 3). Kept
from v2: point-mass sim, shared MLP (39 -> 64 -> 64 -> 2), BPTT training,
Chamfer + collision (+ spacing) loss / s^2, cosine lr, benchmark + early
stopping.

------------------------------------------------------------------------------
1. WHAT CHANGED (v2 -> v3) AND WHY
------------------------------------------------------------------------------

  Goals       v2: M = 1-8 x N points spread evenly by length (sample_strokes).
              v3: exactly N goal SLOTS from swarm/layout.py: a slot at every
              stroke end, corner (turn > 35 deg) and junction ("anchors"),
              the rest spread evenly, no two slots closer than 0.6 spacings.
              Why: drone shows place one drone per slot; with M > N, corners
              and short strokes were cut (an M lost its points).
  Sizes       v2: 11 fixed (N, M) cells.  v3: N drawn uniformly from 8-96
              for every batch.  Why: one policy for any swarm size.
  Text        v2: hand-made A-Z font.  v3: Hershey Simplex (single stroke,
              A-Z and 0-9).  Training families add "random_string" (1-4
              letters/digits); "letters" is 1-2 letters. Strings must pass the
              feature-size rule for the batch's N or are redrawn.
  Held out    star, heart, spiral, words HI UMD LOVE FIRE MARRY ME, and 12
              fixed strings. None can be generated in training (excluded by
              exact string; MARRY ME also excludes MARRY and ME).
  Rule        feature-size rule along-the-shape threshold 3 -> 6 spacings
              (sharp Hershey corners failed at any N with 3).
  Scoring     v2: ratio to the per-scene optimum (Chamfer).  v3: slot
              metrics from one-to-one matching (below). The ratio is kept as a
              secondary number; with M = N the optimum is ~0, so the ratio is
              mostly Chamfer / (0.01 s^2).
  Selection   best checkpoint and early stopping use the mean slot error
              (smooth) instead of the ratio.
  Benchmark   data/benchmark_v3/, N in {8, 16, 24, 32, 48, 64, 96}, 4 scenes
              per family per N (36 training-family scenes, up to 20 held-out),
              per-scene optimum stored with its slot metrics.
  Names       v3 outputs: runs/phase2_v3_<exp>/, results/models/
              phase2_v3_<exp>.pt, results/*/phase2_v3_*. v2 files untouched;
              v2 notebooks archived in notebooks/v2/.

------------------------------------------------------------------------------
2. SLOT METRICS (swarm/metrics.py)
------------------------------------------------------------------------------

All at the final step, per scene, then averaged. Distances in drone spacings
s = outline length / N (so scenes of any size compare).

  Matching     drones and slots are paired one-to-one by the Hungarian
               algorithm (scipy linear_sum_assignment), minimizing the total
               drone-slot distance.
  slot error   mean matched distance / s.  0 = every slot hit exactly.
  slots filled share of slots whose matched drone is within d_min = 0.4 s.
               Also split into anchor slots and fill slots.
  steps to     first step t after which the slot error stays below 0.5
  form         spacings until the end of the run (slot error computed at
               every step). nan if never; reported as the median over the
               scenes that formed, plus "formed" = share that did.
  shared goals share of slots that are the NEAREST slot of 2+ drones: a
               pile-up that leaves a neighbor empty (not matching-based; it
               shows why slots are empty).

Chamfer does not see a pile-up: two drones on one slot and an empty slot one
spacing away cost about as much as a slightly uneven formation. The matching
metrics do.

------------------------------------------------------------------------------
3. SEEDS (fixed: every run and every baseline sees the same scenes)
------------------------------------------------------------------------------

  Benchmark       BENCH_SEED = 2026. Cell for N = BENCH_N[i], split j
                  (0 = train, 1 = held-out) is built with seed 2026 + 100 i + j:
                  N=8: 2026/2027, 16: 2126/2127, 24: 2226/2227, 32: 2326/2327,
                  48: 2426/2427, 64: 2526/2527, 96: 2626/2627.

------------------------------------------------------------------------------
5. PROBLEMS FOUND (v3)
------------------------------------------------------------------------------

  1. Loss / metric mismatch (expected, now measured). Chamfer has no
     one-to-one constraint. During training the Chamfer loss kept falling
     (4.7 -> 0.4 per s^2) while the slot error rose after iteration 500-1000;
     18-25% of slots end as the nearest slot of 2+ drones. Even the per-scene
     optimum, which also optimizes Chamfer, fills only 72-76% (53% at N=96).
     Proposed fix (not implemented): a soft one-to-one matching term, e.g. a
     Sinkhorn optimal-transport loss (GeomLoss-style, uniform weights, M = N)
     added to or replacing Chamfer; its gradient pulls each drone toward its
     share of the slots instead of the nearest one.
  2. Stroke ends and corners are under-filled, not over-filled: anchors 41%
     vs fill slots 49% (optimum 84 vs 73%). Drones bunch in the middle of
     strokes and don't reach the ends. A matching loss addresses this too;
     the observation could also flag anchor slots.
  3. Model selection metric. Slot error (mean distance) and slots filled
     disagree late in training: a few far-away drones raise the mean while
     more slots fill. Early stopping on slot error kept the v3 baseline at
     iteration 500 (29% filled); its last checkpoint fills 37% (held-out 45%).
     For v3 spacing it doesn't matter (42% either way, fewer collisions at
     the end). Next runs: select on slots filled, or on a matching loss.
  4. Large swarms. Filled falls with N (v3 spacing 55% at N=8 -> 33% at 96);
     almost no scene with N >= 32 stays below 0.5 spacings of slot error, so
     "steps to form" is only defined for small N (medians come from 2-16% of
     scenes; treat them with care).
  5. Phase 1 lesson carried over: scoring only the last frame makes plans
     arrive just in time. Phase 1 text plans now score every step
     (hold_frac=1.0). The policy scores the last 20% of steps; the benchmark
     optimum still uses the last frame (kept for comparability).
