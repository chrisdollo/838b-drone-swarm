==============================================================================
PHASE 1. SETUP AND FOUNDATIONS
==============================================================================

------------------------------------------------------------------------------
1. BIG PICTURE
------------------------------------------------------------------------------

Goal: prove that gradients flow through our own simulator before any neural
network is involved.

The test: 32 agents start at random positions. We do not use a policy.
Instead, we directly optimize the full list of accelerations (every agent,
every time step). We run the simulation, measure how far the final positions
are from a circle, backpropagate that error through all 100 steps, and update
the accelerations. Repeat 300 times.

If the agents end up forming a circle, then three things are correct:
  - the simulator is differentiable
  - the shape loss is correct
  - autograd connects the loss to the actions through every step

Why do this first: in Phase 2 the accelerations come from a neural network.
If training fails there, we will know the bug is in the network or the
observations, not in the simulator or the loss.

The pipeline:

  raw params --tanh--> accelerations --sim.rollout--> final positions
                                                           |
  Adam <-- gradient (BPTT) <-- Chamfer loss vs circle <----+

What exactly we optimize:
  The accelerations. 32 drones x 100 steps x 2 directions (x, y) = 6,400
  numbers: what each drone's motors do at each moment.

  We store them as raw numbers r and compute a = a_max * tanh(r).
    - tanh squashes any number into (-1, 1), so a always stays in [-2, 2].
    - Each r gives exactly one a, so choosing r = choosing a.
      r = 0 -> a = 0,  r = 1 -> a = 1.52,  r = 1000 -> a = 2 (never more).

  Why a limit at all: a_max = 2 is the motor limit (max 2 units/s^2 in x
  and in y). Without it the optimizer cheats: huge accelerations, and the
  drones jump onto the circle in one frame. The box is 1 unit wide, so the
  limit still leaves plenty of reach.

  Why not optimize a directly and clip it:
    - clamp(a, -2, 2) inside the sim gives 0 gradient past the limit, so
      that action gets stuck. tanh always has a nonzero slope.
    - Clipping after each Adam step would work for Phase 1.
    - The real reason is Phase 2: the network's output goes through the
      same a = a_max * tanh(output). Phase 1 tests that exact path. Only
      the source of r changes:
        Phase 1: r = 6,400 free numbers     -> tanh -> simulator
        Phase 2: r = MLP(drone observation) -> tanh -> simulator

------------------------------------------------------------------------------
3. FILE BY FILE
------------------------------------------------------------------------------

--- configs/default.yaml -----------------------------------------------------

  dim: 2         Spatial dimension (2D). Set to 3 later for 3D.
  n_agents: 32   Number of agents N.
  dt: 0.05       Seconds per simulation step.
  steps: 100     Rollout length T. dt * steps = 5 seconds of motion.
  damping: 0.5   Drag coefficient c. Slows agents down each step.
  a_max: 2.0     Maximum acceleration. Actions are a_max * tanh(raw).
  seed: 0        Random seed, so every run is repeatable.

Why define them now:
  - Every later phase uses the same simulator settings. If they lived inside
    the code, the baselines and experiments could silently use different
    values, and the comparisons would be unfair.
  - One file per run means any result can be reproduced from its config.
  - dim is a setting from day one, so switching to 3D is a one-line change.

Why these values:
  - dt * steps = 5 s gives agents enough time to cross the unit box.
  - damping > 0 shrinks velocity a little each step. That keeps agents from
    drifting forever and keeps gradients from exploding over 100 steps.
  - a_max mimics real motor limits.

--- swarm/config.py ----------------------------------------------------------

  load_config(path) reads the YAML and returns an object with attribute
  access (cfg.dt instead of cfg["dt"]). Every script calls it first.

--- swarm/sim.py -------------------------------------------------------------

What it does: moves every agent forward in time. All state tensors have
shape [B, N, dim] (batch, agents, dimension).

  step(pos, vel, acc, dt, damping)
    One time step:
      v_new = (1 - c*dt) * v + a * dt     acceleration changes velocity
      p_new = p + v_new * dt              velocity changes position
    Uses the NEW velocity to update position (semi-implicit Euler), which is
    more stable than using the old one.

  rollout(pos0, vel0, accs, cfg)
    Calls step T times and returns the whole trajectory, shape
    [B, T+1, N, dim]. We keep every frame (not just the last) because the
    GIF needs all of them, and so will the Phase 2 collision penalty.

Rules that keep it differentiable:
  - Only PyTorch operations. No NumPy, no .item(), no .numpy() in the loop:
    each of these cuts the gradient chain.
  - No in-place ops (+=). Autograd needs the old values for the backward
    pass.

Check we ran: gradients reached every time step. Early actions get about
37x larger gradients than the last one because they have more time to move
the agent. Damping is what caps that ratio near 37 instead of 100.

Phase 2 change: accs[:, t] is replaced by the policy's output at step t.

--- swarm/shapes.py ----------------------------------------------------------

What it does: makes the target shape as a set of points Q, shape [M, dim].
A shape is just points, so the loss works the same for any shape.

Conventions:
  - The world is the box [-0.5, 0.5]. Every shape is centered at 0 and
    scaled so its larger side is EXTENT = 0.8, leaving a 0.1 margin.
  - We use M = 2N = 64 points so the shape is densely described.
  - For dim = 3 the shape lies flat at z = 0.

  sample_shape(name, m, dim, vertices=None, closed=False)
    circle    q_j = 0.4 (cos(2 pi j/m), sin(2 pi j/m)), evenly spaced angles
    square    closed polyline through the 4 corners
    line      open polyline, 2 endpoints
    polyline  any vertex list (letters, user drawings); closed=True joins
              the end back to the start

  sample_polyline(vertices, m, closed)
    Places m points evenly by ARC LENGTH along the whole outline, not per
    edge. So a long edge gets more points than a short one and the shape is
    covered uniformly. How: add up segment lengths, pick m evenly spaced
    distances along the total, and interpolate inside the segment each one
    falls in. A closed shape stops one gap short, so the last point does
    not duplicate the first.

  normalize(points)
    Centers the bounding box and scales its larger side to 0.8, so a
    user-drawn shape of any size fits the box.

Check we ran: every shape gives 64 points within [-0.4, 0.4]. Spacing is
even (circle 0.039, square 0.050, line 0.013). For the letter L, points are
evenly spaced along the outline; only the jump across the corner is shorter.

Why this matters later: Phase 2 samples a random shape per batch, and
Phase 4 tests on unseen shapes. Both just call sample_shape.

--- swarm/losses.py ----------------------------------------------------------

What it does: scores how well the agents cover the shape.

  chamfer(P, Q)
    P: agents [B, N, dim]. Q: targets [B, M, dim] or [M, dim].
    D[i, j] = ||p_i - q_j||^2 for every agent/target pair, then
      A = mean over agents of (distance to nearest target)   no stragglers
      B = mean over targets of (distance to nearest agent)   no gaps
      L = A + B, averaged over the batch.
    No agent is assigned a target; each min picks the nearest one right now.
    Both terms are needed: with A alone, all agents can pile onto one point.

  pairwise_sq_dist(P, Q)
    Builds D from coordinate differences instead of torch.cdist(P, Q) ** 2.
    cdist takes a square root and we would square it again; the square root
    has an infinite slope at distance 0 (agent exactly on a target point).
    This form is exact and smooth everywhere.

Phase 2 adds the collision and effort penalties to this file.

--- swarm/viz.py -------------------------------------------------------------

What it does: turns results into pictures. No gradients needed, so tensors
are detached first.

  save_gif(traj, Q, path)    One rollout as a GIF: target points as hollow
                             circles, agents as dots, a step counter. Holds the
                             last frame for 1 s before looping.
  plot_loss(history, path)   Loss per iteration on a log scale, with an
                             optional "best possible" reference line.

--- scripts/toy_optimize.py --------------------------------------------------

What it does: runs the whole Phase 1 test.
  uv run python -m scripts.toy_optimize            (circle)
  uv run python -m scripts.toy_optimize --shape square

  1. Random start positions in the box, zero velocity, B = 1.
  2. raw = zeros [1, T, N, 2], requires_grad. Adam, lr 0.05.
  3. 300 times: a = a_max * tanh(raw) -> rollout -> chamfer(final, circle)
     -> backward -> Adam step -> lr schedule step.
  4. Prints the loss every 10 iterations, then saves
     results/gifs/toy_<shape>.gif and results/figures/toy_<shape>_loss.png.

Result: circle loss 0.033 -> 0.00065 in 0.7 s. Best possible is ~0.00058.
Square: 0.031 -> 0.0011.

The learning rate decays to 0 (cosine schedule). Without it the run fails;
see "Surprise" below.

--- tests/ -------------------------------------------------------------------

Run: uv run pytest   (25 tests, about 2 s)

  test_sim.py      rollout output shape; constant velocity when a = c = 0;
                   velocity decays as lambda^t without thrust; final position
                   equals the closed form p_0 + sum w_s a_s; gradcheck on step.
  test_shapes.py   right point count, inside the box; circle radius 0.4;
                   even spacing on closed shapes; polyline normalized to 0.8;
                   3D lies flat; unknown name raises.
  test_losses.py   chamfer(P, P) = 0; symmetric; worked example = 0.26;
                   collapsing onto one point is penalized; gradcheck.

gradcheck compares autograd's gradient to a finite-difference estimate in
float64. If they agree, the backward pass is correct.

pyproject.toml got a [tool.pytest.ini_options] block so tests can import
swarm from the repo root.


------------------------------------------------------------------------------
SURPRISE (for the progress report)
------------------------------------------------------------------------------

1. A constant learning rate breaks the toy optimization.
   With Adam at lr 0.05 the loss reaches 0.00062 by iteration ~185, then
   climbs back to 0.027 by iteration 300. Saturation is not the cause
   (|raw| stays below 0.1). Adam steps every parameter by about lr however
   small its gradient is. One aligned step can move a final position by up
   to a_max * lr * sum(w_s) = 2 * 0.05 * 6.41 = 0.64 units, while the
   target points are 0.04 apart. Near the optimum the agents keep
   overshooting.
     constant lr 0.05:  best 0.00062, final 0.027
     constant lr 0.01:  final 0.00078 (stable, slower)
     cosine from 0.05:  final 0.00065 (stable)  <- used
   The same effect causes the loss spike to ~0.3 in the first iterations.

2. The best loss is not 0, and the best spot is not on a target point.
   With M = 2N, each agent covers two points a spacing s apart. Sitting a
   quarter of the way between them gives A = s^2/16, B = 5 s^2/16, so
   L = 3/8 s^2 = 0.00058. The optimizer reaches 0.00065.

3. Agents arrive only at the end. The loss scores only the final positions,
   so at step 50 the swarm is still scattered. Phase 2 can add a loss on
   intermediate steps if earlier arrival is wanted.
